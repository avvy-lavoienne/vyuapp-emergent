# Playwright storageState Setup

## Overview

This project uses Playwright's `storageState` feature to persist authentication state across E2E tests. This means:

1. **Login once** in `global-setup.ts` via UI
2. **Reuse cookies** in all test files automatically
3. **Faster tests** — no need to login via UI for each test

## How It Works

### 1. Global Setup (`tests/e2e/global-setup.ts`)

- Loads `.env` and `.env.local` files
- Launches headless Chromium browser
- Navigates to `/admin/login`
- Fills login form with admin credentials
- Saves cookies + localStorage to `tests/e2e/.auth/admin-storage-state.json`

### 2. Playwright Config (`playwright.config.ts`)

```typescript
use: {
  storageState: storageStatePath,  // Auto-loaded for all tests
}
```

### 3. Test Files

All tests automatically receive authenticated state. No need to call `loginAs()` in each test.

## File Structure

```
tests/e2e/
├── .auth/
│   └── admin-storage-state.json  # Generated by global-setup
├── global-setup.ts               # Performs login, saves storageState
├── admin-auth.spec.ts
├── admin-crud.spec.ts
└── ...
```

## Environment Variables

Required in `.env` or `.env.local`:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_ADMIN_EMAIL=admin@vyuapp.my.id
SUPABASE_ADMIN_DEFAULT_PASSWORD=your-password
```

## Running Tests

```bash
# Run all E2E tests
npm run test:e2e

# Run specific test
npx playwright test tests/e2e/admin-crud.spec.ts
```

## Troubleshooting

### "Missing NEXT_PUBLIC_SUPABASE_URL"

Ensure `.env` or `.env.local` exists with Supabase credentials.

### "Login failed"

1. Check admin credentials in `.env`
2. Ensure Supabase project is accessible
3. Check if rate limiting is blocking login

### StorageState not found

Run `npm run test:e2e` to regenerate the storageState file.

## Security Notes

- `.auth/` directory is gitignored
- Never commit `admin-storage-state.json`
- Credentials are loaded from environment variables, not hardcoded
